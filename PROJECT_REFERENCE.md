## 1. Project Overview

**BookBot AI** is a full-stack web application that acts as an AI-powered study assistant. A user uploads a document (PDF, TXT, or DOCX) or pastes raw text, and BookBot:

1. Extracts the raw text from the document.
2. Sends the text to **Google Gemini** (`gemini-3.6-flash`) to generate a structured summary with key points and a difficulty rating.
3. Lets the user generate a **multiple-choice quiz** (5, 10, 20, or custom number of questions) derived exclusively from the document's actual content.
4. Provides a **live chat interface** where the user can ask the AI tutor questions about the uploaded document.

The app deliberately does **not** use generic AI knowledge — every summary, quiz question, and chat answer must be grounded in the uploaded document's content.

**Authentication**: The application requires a user account (email + password). All AI feature endpoints (`/upload`, `/summarize`, `/quiz`, `/chat`) are protected behind JWT authentication. Public routes are `/`, `/health`, `/auth/signup`, and `/auth/login`. Google OAuth is planned as a future enhancement and is **not** included in the current implementation.

> **API version**: `api.py` declares `version="2.0.0"` in the FastAPI app object.

## 4. Backend — Deep Dive

### 4.1 Entry Points

| Script | Command | Purpose |
|---|---|---|
| `run_api.py` | `python run_api.py` | **Primary way to start the server.** Uvicorn on port 8000 with `reload=True`. |
| `api.py` | `python api.py` | Alternative direct entry (same config). |
| `main.py` | `python main.py` | CLI chatbot mode — interactive terminal. Not used by the web app. |

### 4.2 Environment Setup

The backend requires `backend/.env`:

```env
GEMINI_API_KEY=your_google_gemini_api_key_here
```

`main.py` loads this at module import time. If the key is missing, a `RuntimeError` is raised immediately — the server fails fast with a clear message.

### 4.3 Core Logic — `main.py`

`main.py` is the **brain** of BookBot. It has no FastAPI knowledge — purely functional Python. `api.py` imports from it.

#### Helper Functions

| Function | Signature | Purpose |
|---|---|---|
| `_strip_code_fences(text)` | `str → str` | Removes ` ```json ... ``` ` fences Gemini sometimes adds around its JSON output. |
| `_coerce_json(text)` | `str → dict` | Robust JSON parser. Tries `json.loads()` then falls back to a bracket-stack scan to find the first complete `{...}` or `[...]` block. Returns `{"error": ..., "raw": ...}` on failure. |

#### File Parsing — `parse_file(file_path)`

Supports three formats:
- **`.txt`** — reads with UTF-8 encoding.
- **`.pdf`** — uses `PyPDF2.PdfReader`, iterates pages, joins non-empty page text with `\n\n`. **Only works on text-layer PDFs, not scanned/image-based ones.**
- **`.docx`** — uses `python-docx`, reads all non-empty paragraphs, joins with `\n\n`.

Raises `FileNotFoundError` or `ValueError` for unsupported formats.

#### Text Validation — `validate_document_text(content)`

Ensures content is not `None`, not empty, and has **at least 50 characters**. Prevents sending garbage content to the AI. Called before every Gemini call.

#### Summary Generation — `generate_structured_summary(content, title)`

- Truncates document to **30,000 characters** (token safety).
- Requires Gemini to return this exact JSON:
  ```json
  {
    "title": "...",
    "summary": "detailed, student-friendly summary",
    "key_points": ["point1", "point2", "point3", "point4", "point5"],
    "difficulty": "beginner|intermediate|advanced"
  }
  ```
- Gemini config: `temperature=0.2`, `top_p=0.9`, `max_output_tokens=2500`, `response_mime_type="application/json"`.
- Validates that `summary` field is present; raises `ValueError` otherwise.

#### Quiz Generation — `generate_quiz_from_text(text, num_q)`

- Accepts `num_q` 1–50 (auto-clamped).
- Truncates document to **30,000 characters**.
- Gemini config: `temperature=0.3`, `top_p=0.9`, `max_output_tokens=5000`.
- Required JSON structure:
  ```json
  {
    "questions": [
      {
        "question": "...",
        "options": ["A", "B", "C", "D"],
        "answer": "exact text of correct option",
        "explanation": "..."
      }
    ]
  }
  ```
- **Python-side validation** after Gemini responds:
  - Non-empty question text required.
  - Exactly 4 non-empty options required.
  - `answer` must exactly match one of the option strings.
  - Invalid questions are silently dropped.
  - Zero surviving questions → raises `ValueError`.

#### Book-Based Quiz — `generate_quiz_from_book()` (Disabled)

Always raises `ValueError`. Intentionally disabled — quizzes must be grounded in uploaded content.

#### Document Chat — `chat_about_document(content, user_message, history)`

- Uses Gemini multi-turn chat (`model.start_chat(history=...)`).
- Converts frontend history `[{"role", "text"}]` to Gemini format `[{"role", "parts": [...]}]`.
- Sends document context + system instructions + user question in a single prompt.
- Gemini config: `temperature=0.3`, `top_p=0.9`, `max_output_tokens=1500`.
- Returns raw reply string.

#### Dynamic Chat — `dynamic_chat(user_input)` (CLI only)

Detects `/cot` prefix for chain-of-thought, keywords like `convert`, `code`, `why`, `how`, `solve`, `explain` for routing. Not used by the web app.

### 4.4 REST API — `api.py`

Built with FastAPI. All routes accept/return JSON except `/upload` (multipart).

**CORS**: `allow_origins=["*"]` — open for local dev. Restrict before production.

**Startup hook**: `@app.on_event("startup")` calls `database.create_tables()` which runs `Base.metadata.create_all()` — creates `bookbot.db` and the `users` table on first run.

**Auth router**: `app.include_router(auth_routes.router)` mounts `/auth/*` endpoints with prefix `/auth`.

| Method | Path | Auth? | Description |
|---|---|---|---|
| `GET` | `/` | ❌ Public | Health: `{"message": "BookBot API is running!"}` |
| `GET` | `/health` | ❌ Public | Health: `{"status": "ok"}` |
| `POST` | `/auth/signup` | ❌ Public | Create account; returns JWT |
| `POST` | `/auth/login` | ❌ Public | Verify credentials; returns JWT |
| `GET` | `/auth/me` | ✅ JWT | Return current user `{id, name, email}` |
| `POST` | `/upload` | ✅ JWT | Upload file; returns extracted text + metadata |
| `POST` | `/summarize` | ✅ JWT | Generate AI summary from document text |
| `POST` | `/quiz` | ✅ JWT | Generate AI quiz from document text |
| `POST` | `/chat` | ✅ JWT | Chat message grounded in document |

All protected routes use `Depends(get_current_user)`. Unauthenticated requests receive HTTP 401.

**`/upload` process**: validate extension → write to `tempfile` → `parse_file()` → validate ≥50 chars → delete tempfile → return `{filename, content, file_type, size, characters_extracted}`.

### 4.5 Auth Backend Files

#### `database.py`

- `DATABASE_URL`: `sqlite:///./bookbot.db` resolved to the absolute path of the `backend/` directory.
- `engine`: created with `connect_args={"check_same_thread": False}` (required for SQLite + FastAPI).
- `SessionLocal`: `sessionmaker(autocommit=False, autoflush=False)`.
- `Base = declarative_base()` — all models inherit from this.
- `create_tables()`: called on startup; idempotent.
- `get_db()`: FastAPI dependency that yields a `Session` and always closes it in `finally`.

#### `models.py`

```python
class User(Base):
    __tablename__ = "users"
    id           = Column(Integer, primary_key=True, index=True)
    name         = Column(String(120), nullable=False)
    email        = Column(String(255), unique=True, index=True, nullable=False)
    password_hash = Column(String(255), nullable=False)
    created_at   = Column(DateTime(timezone=True), default=utcnow)
```

`email` has a unique index — duplicate signups return HTTP 409.

#### `auth.py`

**Password hashing** — uses `bcrypt` library directly (bypasses `passlib` to avoid a known incompatibility with bcrypt ≥5.x — see Gotchas):

```python
def hash_password(plain: str) -> str:
    return bcrypt.hashpw(plain.encode('utf-8'), bcrypt.gensalt(rounds=12)).decode('utf-8')

def verify_password(plain: str, hashed: str) -> bool:
    return bcrypt.checkpw(plain.encode('utf-8'), hashed.encode('utf-8'))
```

**JWT** (`python-jose`):

```python
def create_access_token(data: dict, expires_delta=None) -> str: ...
def decode_access_token(token: str) -> dict:  # raises JWTError on invalid/expired
```

Token payload: `{"sub": "<user_id>", "exp": <datetime>}`. `sub` is the user's integer ID stored as a string.

**Pydantic schemas**:

| Schema | Fields | Used by |
|---|---|---|
| `UserCreate` | `name`, `email` (EmailStr), `password` | `POST /auth/signup` |
| `UserLogin` | `email` (EmailStr), `password` | `POST /auth/login` |
| `UserOut` | `id`, `name`, `email` | `GET /auth/me` response |
| `Token` | `access_token`, `token_type="bearer"` | Login + Signup responses |

`UserCreate` validators: name not empty (≤120 chars), password ≥8 chars.

**`get_current_user()` dependency**:

```python
def get_current_user(
    credentials: HTTPAuthorizationCredentials = Depends(HTTPBearer(auto_error=False)),
    db: Session = Depends(get_db),
) -> User:
```

- Returns HTTP 401 if no credentials, invalid JWT, expired JWT, or user ID not found in DB.
- `auto_error=False` means missing header returns `None` credentials (not a 403), which the function converts to a 401.

#### `auth_routes.py`

FastAPI router with prefix `/auth`:

- **`POST /auth/signup`** (201): Hash password → insert User → return JWT. Duplicate email → 409 `"An account with this email address already exists."`
- **`POST /auth/login`** (200): Look up user → `verify_password()` → return JWT. Wrong email or password → same generic 401 `"Invalid email or password."` (prevents email enumeration).
- **`GET /auth/me`** (200): `Depends(get_current_user)` → return `UserOut` (no `password_hash`).

## 5. Frontend — Deep Dive

### 5.1 App Shell & Routing (`App.jsx`)

`App.jsx` now has two layers:

1. **`App` (root)** — defines the React Router routes:
   - `/login` → `<LoginPage />` (public)
   - `/signup` → `<SignupPage />` (public)
   - `/` → `<ProtectedRoute><BookBotApp /></ProtectedRoute>`
   - `*` → `<Navigate to="/" replace />`

2. **`BookBotApp`** — the original BookBot SPA logic, with the Welcome Transition overlay wired in. Rendered only when authenticated.

`BookBotApp` reads `{ user, logout, showWelcome, isNewUser, clearWelcome }` from `useAuth()`. The welcome overlay is rendered at the bottom of `BookBotApp`'s JSX:

```jsx
{showWelcome && (
  <WelcomeTransition
    userName={user?.name}
    isNewUser={isNewUser}
    onDone={clearWelcome}
  />
)}
```

This overlay sits above all other content (`z-index: 9999`) and auto-dismisses after ~2.6 s. It is **not** shown on session restore — only after a live login or signup action.

**BookBotApp state** (unchanged from pre-auth):

| State | Type | Description |
|---|---|---|
| `uploadedFile` | `File \| null` | Raw browser `File` object |
| `fileContent` | `string` | Extracted text from `/upload` |
| `summary` | `object \| null` | Normalized summary from AI |
| `quiz` | `object \| null` | Validated quiz `{questions: [...]}` |

**Quiz normalization in App.jsx** (second pass after backend): checks non-empty question, exactly 4 non-empty options, answer exists in options. Invalid questions filtered out.

**Header user UI**: `.app-header` now uses `justify-content: space-between`. Right side: `.app-header-user` div containing `.app-header-greeting` (`👋 {user.name}`) and `.logout-btn` (outlined Smoky Rose button).

### 5.2 Component: FileUpload

**Props**: `{ onFileUpload }`

Two input modes toggled by tab buttons:
1. **File mode** — drag-and-drop zone. Calls `apiService.uploadFile(file)` → `onFileUpload(file, response.content)`. The file `<input>` accepts `.pdf,.txt,.docx,.doc,image/*`.
2. **Text paste mode** — `<textarea>` (8 rows). Creates mock file object (`{name: 'Text Input', type: 'text', size: textInput.length}`), adds a **1-second artificial delay** (`setTimeout(resolve, 1000)`), then calls `onFileUpload(mockFile, textInput.trim())` directly **without any backend call**.

**Text mode extras**: Live character counter (`textInput.length characters`) displayed below the textarea. Submit button disabled until textarea has non-whitespace content.

Local state: `isDragOver`, `isProcessing`, `textInput`, `inputMode`.

**Feature panel**: Below the upload zone there's an `.upload-features` strip showing three feature badges: "AI-Powered Summarization", "Generate Custom Quizzes", "Fast Processing".

> **Note**: The file `accept` attribute includes `image/*`, but the backend `/upload` only processes `.pdf`, `.txt`, `.docx`. Uploading an image will trigger a backend 400 error.

### 5.3 Component: SummaryDisplay

**Props**: `{ file, content, onSummaryGenerated, onGenerateQuiz, onStartChat, onReset }`

Auto-triggers `generateSummary()` on mount via `useEffect([content])`. Guard: only triggers when `content` is truthy **and** `summary` is null.

Summary fields mapped from backend into the normalized object:
```
summaryData.title       → title  (fallback: file.name → 'Document')
summaryData.type        → type   (fallback: file.type → 'document')  ← NEW field
summaryData.summary     → summary
summaryData.key_points  → highlights  (fallback: summaryData.highlights → [])
summaryData.difficulty  → difficulty  (fallback: 'intermediate')
computed                → word_count  (content.trim().split(/\s+/).filter(Boolean).length)
content.length          → char_count
```

Summary header: The `.file-info` div is rendered but intentionally empty (`{/* File information intentionally hidden */}`).

Highlights section: Section heading reads **"✨ Topic Highlights"** (not "Key Points"). Items use the `.stagger-list` animation class.

Actions section layout: Chat button appears **above** quiz buttons. Chat button is disabled when `isQuizGenerating === true`.

Quiz size buttons: Quick (5q), Standard (10q), Comprehensive (20q), Custom (`window.prompt` 1–20).

Error display: After a successful summary load, any subsequent error (e.g. quiz failure) shows inline as an `.error-state` div **inside** the actions section (does not replace the whole component).

States: `summary`, `isGenerating`, `isQuizGenerating`, `error`.

### 5.4 Component: QuizInterface

**Props**: `{ quiz, onBackToSummary, onReset }`

Four render states:
1. **No data guard** — if `quiz` or `quiz.questions` is falsy, shows error + "Back to Summary" button.
2. **Intro** — question count + formatted time limit (10:00), instructions bullet list, "Start Quiz 🚀" + "Back to Summary" buttons.
3. **Active** — one question at a time, progress bar (`width: ${progress}%`), timer (`⏰ MM:SS`), question indicators (clickable dots showing current/answered states), Prev/Next nav. Last question's Next button reads "Finish".
4. **Results** — score % circle (`score-circle`) + fraction display (`correct/total`), color-coded `.score-display` with class modifier (`excellent`/`great`/`good`/`okay`/`needs-work`), per-question breakdown showing user answer and correct answer for wrong answers, three action buttons.

Results action buttons: **"🔄 Retake Quiz"** (resets all state back to intro), **"📖 Back to Summary"**, **"📄 New Document"** (`onReset`).

Score messages: ≥90% "Excellent! 🎉", ≥80% "Great job! 👏", ≥70% "Good work! 👍", ≥60% "Not bad! 💪", <60% "Keep studying! 📚".

Active quiz also has persistent "Back to Summary" + "New Document" buttons below the navigation row.

Timer: `useEffect` runs a `setInterval` every 1000ms when `quizStarted && timeLeft > 0 && !showResults`. Cleanup via returned `clearInterval`.

State: `currentQuestion`, `selectedAnswers` (map `{index: answerText}`), `showResults`, `timeLeft` (starts 600), `quizStarted`.

### 5.5 Component: DocumentChat

**Props**: `{ content, onBack }`

- Starts with a welcome `model` message: *"Hi! I have read the document you uploaded. Feel free to ask me anything about it!"*
- **Critical**: filters this welcome message from history before sending to `/chat` — uses `messages.filter((msg, idx) => !(idx === 0 && msg.role === 'model'))`. This ensures Gemini history never starts with a `model` turn.
- Auto-scrolls via `messagesEndRef` — scrolls on both `messages` and `isTyping` changes.
- Shows typing indicator (three animated `<span>` dots inside `.typing-indicator`) while waiting.
- Enter key triggers send via `onKeyPress={(e) => e.key === 'Enter' && handleSend()}`.
- Send button is disabled when `isTyping || !input.trim()`.
- On error, pushes a `model` message with text: *"Sorry, there was an error processing your request. Please try again."*
- Header includes a **"← Back to Summary"** button that calls `onBack`.

### 5.6 Service Layer — `api.js`

Singleton `ApiService` class.

**Base URL**: `import.meta.env.VITE_API_URL || 'http://localhost:8000'`. Trailing slash stripped via `.replace(/\/$/, '')`.

**Token injection**: Every request goes through `request()`, which reads `localStorage.getItem('bookbot_token')` and adds `Authorization: Bearer <token>` to the headers automatically. Components never handle the token directly.

**Token storage key**: `'bookbot_token'` (same constant used in both `api.js` and `AuthContext.jsx`).

**401 handling**: When the backend returns 401, `request()` calls `localStorage.removeItem('bookbot_token')` and throws an error with the detail message. `AuthContext` will see the next state-restoring call to `/auth/me` fail and clear the user, triggering a redirect to `/login`.

| Method | Endpoint | Auth? | Notes |
|---|---|---|---|
| `login(email, password)` | `POST /auth/login` | ❌ | Returns `{access_token, token_type}` |
| `signup(name, email, password)` | `POST /auth/signup` | ❌ | Returns `{access_token, token_type}` |
| `getCurrentUser()` | `GET /auth/me` | ✅ auto | Returns `{id, name, email}` |
| `uploadFile(file)` | `POST /upload` | ✅ auto | `multipart/form-data` |
| `generateSummary(content, title)` | `POST /summarize` | ✅ auto | JSON body |
| `generateQuiz(content, questionCount)` | `POST /quiz` | ✅ auto | Validates 1–50 count client-side; validates non-empty `questions` in response |
| `sendChatMessage(content, message, history)` | `POST /chat` | ✅ auto | `history` coerced to `[]` if not array |

## 6. Authentication System

### 6.1 Architecture Overview

```
localStorage["bookbot_token"] = "eyJ..."
         │
         ▼
AuthContext (wraps entire app in main.jsx)
  ├─ on mount → GET /auth/me → restore session (or clear stale token)
  ├─ login()  → POST /auth/login → store token → navigate('/')
  ├─ signup() → POST /auth/signup → store token → navigate('/')
  └─ logout() → localStorage.removeItem('bookbot_token') → navigate('/login')

React Router (react-router-dom v6+)
  /login   → LoginPage  (public — no redirect if already authed)
  /signup  → SignupPage (public)
  /        → ProtectedRoute → BookBot SPA
  /*       → Navigate to /

api.js request() helper (all requests)
  → reads bookbot_token from localStorage
  → adds Authorization: Bearer <token>
  → 401 response → auto-clears token

FastAPI backend
  /auth/signup   POST   public
  /auth/login    POST   public
  /auth/me       GET    protected (get_current_user dep)
  /upload        POST   protected (get_current_user dep)
  /summarize     POST   protected (get_current_user dep)
  /quiz          POST   protected (get_current_user dep)
  /chat          POST   protected (get_current_user dep)
  /              GET    public (health)
  /health        GET    public (health)

SQLite (backend/bookbot.db)
  users: id | name | email (UNIQUE) | password_hash | created_at
```

### 6.2 AuthContext (`context/AuthContext.jsx`)

**Provides via `useAuth()` hook**:

| Value | Type | Description |
|---|---|---|
| `user` | `{id, name, email} \| null` | Current user; `null` = not logged in |
| `isAuthenticated` | `boolean` | `user !== null` |
| `loading` | `boolean` | `true` during initial session restore on mount |
| `login(email, password)` | `async fn` | Calls API → stores token → sets user → **sets `showWelcome=true`, `isNewUser=false`** → navigates to `/` |
| `signup(name, email, password)` | `async fn` | Calls API → stores token → sets user → **sets `showWelcome=true`, `isNewUser=true`** → navigates to `/` |
| `logout()` | `fn` | Clears token → sets `user = null` → **resets `showWelcome=false`** → navigates to `/login` |
| `showWelcome` | `boolean` | ★ NEW — `true` only after a live login or signup (never on session restore) |
| `isNewUser` | `boolean` | ★ NEW — `true` when a signup triggered the welcome; `false` after login |
| `clearWelcome()` | `fn` | ★ NEW — called by `WelcomeTransition.onDone`; resets both `showWelcome` and `isNewUser` to `false` |

**Session restore** (on mount): reads `localStorage.getItem('bookbot_token')`. If token exists, calls `apiService.getCurrentUser()` (`GET /auth/me`). On success: sets `user`. On failure (expired/invalid): silently removes the token. Either way, sets `loading = false`. **`showWelcome` is intentionally NOT set during session restore** — the transition is only triggered by interactive login/signup.

**`ProtectedRoute` waits for loading**: renders a full-page spinner while `loading === true` to prevent a flash-of-redirect during session restore.

| Concern | Approach |
|---|---|
| Storage | `localStorage` (standard SPA + REST API pattern) |
| Token key | `'bookbot_token'` |

## 8. API Reference

**Dev Base URL**: `http://localhost:8000`
**Prod Base URL**: Set via `VITE_API_URL` env var

**Auth header** (required for all protected routes):
```
Authorization: Bearer <JWT access token>
```

### `POST /auth/signup` — Public
- Request: `{"name": "...", "email": "...", "password": "..."}`
- Response 201: `{"access_token": "...", "token_type": "bearer"}`
- Error 409: duplicate email — `"An account with this email address already exists."`
- Error 422: validation failure (missing fields, bad email format, password < 8 chars)

### `POST /auth/login` — Public
- Request: `{"email": "...", "password": "..."}`
- Response 200: `{"access_token": "...", "token_type": "bearer"}`
- Error 401: wrong email or password — `"Invalid email or password."` (generic to prevent email enumeration)

### `GET /auth/me` — Protected
- Header: `Authorization: Bearer <token>`
- Response 200: `{"id": 1, "name": "Test User", "email": "test@example.com"}`
- Error 401: missing/invalid/expired token

### `POST /upload` — Protected
- Request: `multipart/form-data`, field `file`
- Allowed: `.pdf`, `.txt`, `.docx`
- Response 200: `{filename, content, file_type, size, characters_extracted}`
- Error 400: bad format, empty file, too little text
- Error 401: no/invalid token
- Error 500: parse failure

### `POST /summarize` — Protected
- Request: `{"content": "...", "title": "..."}`
- Response 200: `{title, summary, key_points: [...], difficulty}`
- Error 400: missing content
- Error 401: no/invalid token

### `POST /quiz` — Protected
- Request: `{"content": "...", "question_count": 10}`
- `question_count` must be integer 1–50
- Response 200: `{questions: [{question, options: [4 strings], answer, explanation}]}`
- Error 400: missing content, invalid count
- Error 401: no/invalid token
- Error 500: Gemini failure or zero valid questions

### `POST /chat` — Protected
- Request: `{"content": "...", "message": "...", "history": [{role, text}]}`
- Response 200: `{"reply": "..."}`
- Error 400: missing content or message
- Error 401: no/invalid token

## 11. Known Patterns & Conventions

### Double Validation of Quiz Questions
Validated **twice** — once in `main.py` (Python), once in `App.jsx` (JS). Intentional redundancy to ensure malformed Gemini output never reaches the UI. The `api.js` `generateQuiz()` also does a third lightweight check (non-empty array).

### Stateless Document Processing
The backend stores no document state. Every request from the frontend sends the **full document text** along with it. No sessions, no document caching. User accounts (names, emails, hashed passwords) are stored in SQLite.

### Auth is Stateless Too
JWTs are verified on every protected request by re-decoding the token — no server-side session table. To invalidate a token before expiry, you would need to introduce a token blacklist (not currently implemented).

### Text Paste Bypasses Backend
"Paste Text" mode in `FileUpload` skips `/upload` entirely and passes text directly through `onFileUpload` with a mock file object. A 1-second artificial delay (`setTimeout(resolve, 1000)`) simulates processing.

### FastAPI Error Messages via `detail`
All `HTTPException` instances set a `detail` string. The frontend `request()` method reads `data?.detail || data?.message || data?.error` in that priority order.

### Stagger Animation Pattern
Lists use the `.stagger-list` class which applies CSS `animation-delay` to the first 5 children (60ms, 120ms, 180ms, 240ms, 300ms) for a cascading reveal effect.

### App Shell Has a Footer
`App.jsx` renders an `.app-footer` below `<main>`: `<p>Powered by AI • Built with React</p>`. Styled in `App.css` with `border-top` and muted color.

### QuizGenerator.jsx Is Documented but Has More Features
`QuizGenerator.jsx` (unused) accepts props `{ onQuizGenerated, isGenerating, error }` and exposes a `quizType` state (`'mixed'` | `'concepts'` | `'details'` | `'application'`). It passes both `questionCount` and `quizType` to `onQuizGenerated`. Options go up to 30 questions (5, 10, 15, 20, 25, 30).

### Summary `type` Field
`SummaryDisplay` populates a `type` field in the normalized summary object from `summaryData.type || file?.type || 'document'`. This field is not currently rendered in the UI but is part of the state object passed to `onSummaryGenerated`.

### Image File Acceptance in Upload Zone
The `<input type="file">` in `FileUpload` accepts `image/*` in addition to PDF/TXT/DOCX. However, the backend will reject images with a 400 error since `api.py` only allows `.pdf`, `.txt`, `.docx` extensions.

## 14. Gotchas & Important Notes

> **Scanned PDFs won't work.** PyPDF2 extracts text-layer only. Image/scanned PDFs return empty text and get rejected with a 400 error.

> **Gemini history must start with "user" role.** `DocumentChat.jsx` filters out the initial welcome `model` message before building the history array. Preserve this if refactoring the chat component.

> **Quiz `answer` must exactly match an option string.** Both backend and frontend use strict equality. If Gemini rephrases the answer, the question is dropped. If too many are dropped, consider tightening the prompt.

> **`gemini-3.6-flash` is hardcoded** in `main.py` line 28. Update if the model is deprecated.

> **CORS is wide open.** `allow_origins=["*"]` is set for local dev. Restrict to your frontend origin before any public deployment.

> **Custom quiz UI caps at 20 questions** (via `window.prompt` validation). Backend allows up to 50. Intentional — the UI is more conservative.

> **`QuizGenerator.jsx` exists but is unused.** It appears to be a leftover from an earlier iteration. The quiz launching UI is inside `SummaryDisplay.jsx`. `QuizGenerator.jsx` also has a `quizType` select that the active quiz flow doesn't expose.

> **The bookbot logo is left-aligned in the header** with `justify-content: space-between`. The right side shows the user greeting + logout button. Changing `justify-content` will break the header layout.

> **`err.txt` and `error.txt` exist in `backend/`** — these are captured stderr/error logs. They are gitignored.

> **`package-lock.json` exists in `backend/`** — artifact from an accidental `npm` invocation. Gitignored.

> **Color palette changed from Deep Burgundy to Smoky Rose.** Actual current tokens are documented in Section 5.7.

> **`passlib 1.7.4` + `bcrypt ≥5.x` are incompatible.** `passlib`'s bcrypt backend-detection runs a 73-byte test password, which `bcrypt 5.x` rejects with `ValueError: password cannot be longer than 72 bytes`. The fix: `bcrypt==4.2.1` is pinned in `requirements.txt`, and `auth.py` calls `bcrypt` directly (not via `passlib.CryptContext`). **Do not upgrade `bcrypt` to 5.x without testing.**

> **`JWT_SECRET_KEY` must be changed before production.** The default placeholder value `"change-this-to-a-strong-random-secret-before-production"` is intentionally weak. Generate a real secret: `python -c "import secrets; print(secrets.token_hex(32))"`.

> **JWT tokens are not revocable** without a token blacklist (not implemented). If a token is stolen, it remains valid until it expires. Reduce `ACCESS_TOKEN_EXPIRE_MINUTES` for higher-security deployments.

> **`bookbot.db` is gitignored.** The SQLite file is created automatically on first run. If you delete it, all user accounts are lost. Back it up before deploying.

> **`main.jsx` wrapping order matters.** The `<AuthProvider>` must be inside `<BrowserRouter>` because `AuthContext` uses `useNavigate()`, which requires a router context.
